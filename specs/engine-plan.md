# Engine plan — deliver meaning in inspectable waves

This is the PM work map. Domain specs remain authoritative for boundaries. No quantity target alone is a quality pass. Every wave has a concrete output, dependency gate, critic task and explicit exclusions.

## M0 — a real first thread

The foundation PR establishes the new root workspace while retaining the earlier `frontend/`. It includes source research, machine-readable registry, contracts, six real artwork fixtures, bounded offline replay, validation, graph operations, rights selection and a thin static demo. It tests two fundamentally different relationships: an explicit study/final work and a shared gesture across regions/centuries.

Root PM owns workspace/contracts/governance/architecture. Three delegated builders own ingest, graph and explorer files; root integrates core/media/site. Their scopes do not overlap. Independent reviewers receive artifacts and bars without builder reports. Any bootstrap execution exception is recorded in the decision log.

## M3 — learning and breadth

Provision the learning domain only for an actual cited guided route. Add source/curator partnerships for underrepresented regions and living traditions; support contemporary records even when no publishable images exist. The coverage matrix determines where new acquisition work is useful. Avoid equating a Western museum's holdings with a culture's entire artistic history.

Optional computational work comes after reliable exploration: visual embeddings, semantic retrieval and seeded surprise suggestions. Each candidate shows input claims/method/version and a visible computed label. It cannot write historical influence into the asserted corpus. A historical-evidence-only mode and all-recorded-neighbors access remain available.

## Required cross-domain change protocol

1. Describe the missing visitor/data capability and one real failing example.
2. PM names owner, changes contract/specs, records migration and new invariants.
3. Split adapter, graph, media and explorer work into separate branches/worktrees.
4. Run technical gates and fresh domain critics on the built result.
5. Integrate/smooth; record unresolved gap and stop decision explicitly.

The plan assigns work; it does not automatically send messages, create issues, deploy a site, or schedule recurring ingestion. Those actions require the corresponding user task/authorization.
